# Case: Hardcoded Patient IDs and Local-Only State Mutations
- **Date:** 2026-11-14
- **Domain:** Engineering
- **Type:** Negative
- **Trigger / Context:** Mobile store mutations (`removeExam`, `deleteUploadedDocument`, `injectWearableAnomalyScenario`, `resetWearableScenario`) and Web token resolution (`entry.tsx`) previously defaulted to `'usr-dan-2026'` or only mutated local Zustand state without persisting to Supabase.

## Pattern / Technique
When `entry.tsx` filtered `doctor_access_sessions` by `.eq('patient_id', 'usr-dan-2026')`, tokens generated by Marcos, Camila, Antônio, or Rafael on the Mobile App were invisible to the Doctor Web Cockpit. Similarly, when `buildPatientSnapshotFromSupabase` ignored `requestedScopes` instead of running `projectFixture(snapshot, activeScopes)`, revoked or unshared scope categories leaked into the clinical snapshot.

## Concrete Artifact / Code Snippet / Prompt
```ts
// ANTI-PATTERN (BANNED):
.eq("patient_id", "usr-dan-2026") // Blocks multi-patient tokens!
set((state) => ({ exams: state.exams.filter((e) => e.id !== id) })); // Local-only delete!
```

## Takeaway & Heuristic
- **Do:** Query active tokens across all patients in `entry.tsx`, apply `projectFixture(snapshot, activeScopes)` in `buildPatientSnapshotFromSupabase`, and execute real Supabase `INSERT`/`UPDATE`/`DELETE` operations on every Mobile and Web action.
- **Don't:** Never leave a CRUD action, review cursor, follow-up request, or token revocation in memory-only state.
